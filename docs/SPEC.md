# Техническое задание

## Telegram-бот автоматической нарезки и монтажа Twitch-клипов

Версия: 1.2 · Дата: 25.11.2026
Базис: версия 1.1 + CR-001 (25.11.2026).

---

## 1. Общее описание

### 1.1. Назначение

Система в автоматическом режиме круглосуточно ищет Twitch-клипы по заданным фильтрам, передаёт найденные клипы администратору на одобрение через Telegram, по одобрению скачивает клип, монтирует из него вертикальное видео (Shorts / Reels / TikTok Format) с вшитыми субтитрами, отправляет результат на повторное одобрение и публикует одобренные видео в облачное хранилище.

### 1.2. Целевые показатели

| Параметр | Значение |
|---|---|
| Выпуск готовых видео | 3–5 шт/день |
| Время от одобрения до готового черновика | ≤ 15 мин на клип |
| Длительность итогового видео | 30–60 сек |
| Входной клип | ≤ 60 сек (жёсткий фильтр парсера, тримминг не выполняется) |
| Формат | 1080×1920 (9:16), MP4, H.264 + AAC |
| Язык контента и субтитров | Русский |
| Хранение | Локальный диск (рабочая область) + Cloudflare R2 (мастера) |
| Размер файла, отправляемого в Telegram | ≤ 45 МБ (предохранитель; целевой диапазон 15–35 МБ) |

### 1.3. Роли

- **Администратор** — единственный пользователь Telegram-бота. Одобряет/отклоняет клипы на двух точках контроля, запрашивает переделку, задаёт фильтры.
- **Система (бот + worker)** — выполняет поиск, скачивание, транскрипцию, монтаж, загрузку в облако.

## 2. Архитектура

### 2.1. Компоненты

1. **Бот (coordinator)** — Telegram-интерфейс (aiogram 3), управление очередью и статусами, рассылка уведомлений.
2. **Парсер** — модуль поиска клипов по фильтрам (Twitch Helix API + при необходимости сторонние источники метаданных).
3. **Worker (тяжёлые задачи)** — скачивание (yt-dlp), извлечение аудио и транскрипция (faster-whisper), генерация `.ass`, рендер (ffmpeg), загрузка в R2 (boto3).
4. **Очередь и состояние** — SQLite (aiosqlite), единый источник истины по статусам. Worker берёт задачи из БД, а не из памяти, поэтому перезапуск не теряет клипы.
5. **Хранилища**:
   - локальные TEMP-каталоги `downloads/`, `audio/`, `rendered/` — с автоочисткой после публикации/отказа;
   - Cloudflare R2 — финальные одобренные мастера: `YYYY/MM/DD/<clip_id>.mp4` + `meta.json`.

### 2.2. Схема процесса

```
Парсинг (круглосуточно, интервал N мин)
  ↓ фильтры: метаданные (просмотры, категория, стример, длительность ≤ 60 сек)
Список кандидатов → dedup по clip_id → БД (статус: new)
  ↓
Модерация №1 (TG): карточка клипа + кнопки [Одобрить] [Отклонить]
  ↓ одобрение
Скачивание → извлечение аудио → Whisper (транскрипт с таймкодами)
  ↓
Генерация .ass → ffmpeg-рендер вертикали (blur-фон + субтитры)
  ↓
Модерация №2 (TG): готовое видео + кнопки [Опубликовать] [На переделку] [Отказ]
  ↓ «Опубликовать»
Загрузка в R2 (+ meta.json) → статус published → очистка TEMP
  ↓
Возврат к парсингу
```

### 2.3. Статусы клипа в БД

`new → sent_to_admin → approved → downloading → transcribing → rendering → sent_for_review → published | rejected | revision | failed`

- `revision` — возврат на переделку с комментарием/правкой админа; из него клип снова попадает в `rendering` (без повторной транскрипции, транскрипт сохраняется в БД).
- `failed` — техническая ошибка; задача ретраится до 3 раз, затем уходит админу с текстом ошибки.

## 3. Функциональные требования

### 3.1. Парсер

- Опрос по расписанию (интервал настраивается, по умолчанию 15 мин) через Twitch Helix API: клипы по играм/категориям/стримерам за период.
- Фильтры (задаются в конфиге и редактируются админом в TG):
  - список категорий (игр) и/или каналов-источников;
  - мин./макс. просмотры;
  - **длительность клипа ≤ 60 сек** (жёсткий фильтр, верхняя граница зафиксирована ТЗ; нижняя настраивается);
  - дата создания клипа (за последние 24 ч);
  - чёрный/белый списки каналов;
  - ключевые слова в названии клипа (опционально).
- Дедупликация по `clip_id`: повторно найденный клип не попадает в очередь повторно.
- Контентные (смысловые) фильтры — опция этапа 2 развития: предварительная классификация короткого листа кандидатов через ASR/визуальную модель.
- Результат: карточка в TG — превью, автор, категория, длительность, просмотры, ссылка.

### 3.2. Модерация №1 (кандидат)

- Кнопки: «Одобрить» / «Отклонить».
- По одобрению клип переходит в pipeline скачивания и монтажа.
- Скачивание выполняется **только после одобрения** (экономия трафика и диска).

### 3.3. Скачивание и обработка

- Скачивание исходного MP4 клипа (yt-dlp или совместимый механизм).
- Извлечение аудио WAV 16 kHz mono (ffmpeg).

### 3.4. Транскрипция

- faster-whisper, модель `medium` (fallback `large-v3`), язык `ru`, `word_timestamps=True`.
- Выход: список слов/сегментов с таймкодами `{start, end, text}`.
- Транскрибация оформлена за интерфейсом `transcribe(audio) -> words[]` — допускает замену провайдера (например, Groq Whisper API) без изменения остального кода.
- Качество ASR повышается детерминированно: `initial_prompt` со списком ников/игр/терминов и словарь замен (`glossary`) из конфига.
> **Триггер fallback `medium → large-v3`:** повтор выполняется один раз на клип, если после первой попытки выполнено хотя бы одно условие:
> - транскрипт пуст или содержит < 5 слов;
> - доля сегментов с `avg_logprob < -1.0` превышает 30 %;
> - доля сегментов с `no_speech_prob > 0.6` превышает 30 %;
> - итоговая длительность распознанной речи < 30 % длительности аудио.
>
> Если fallback тоже не дал результата — клип переходит в `failed` с текстом причины. Больше одной попытки fallback не делается.
- LLM-нормализация текста (пунктуация, жаргон) — **не в v1**, точка расширения: отдельный опциональный этап `normalize(words) -> words` за флагом, с сохранением числа слов и фолбэком на сырой транскрипт. Таймкоды модель не трогает никогда.
- Постобработка: удаление повторов/заиканий, разбиение на строки ≤ 25 символов / ≤ 6 слов с синхронизацией по таймкодам слов.

### 3.5. Субтитры

Цепочка: **faster-whisper (текст + таймкоды) → постобработка → генерация `.ass` нашим кодом → libass внутри ffmpeg (фильтр `ass=`)**.

- Формат `.ass`, вшивание в кадр (burn-in) на этапе рендера — отдельного шага прожига нет, всё в одном проходе ffmpeg.
- Стилистика (настраивается в конфиге):
  - жирный шрифт с кириллицей (Montserrat ExtraBold / Inter Black), белый, чёрная обводка 4–6 px, размер 64–72 px при 1080×1920;
  - позиция: центр по горизонтали, 55–65 % высоты кадра (вне safe zones TikTok/Reels);
  - режим отображения: слово-за-словом (karaoke, теги `\k`) — базовый вариант; построчные фразы — упрощённый fallback.
- Опциональный второй слой: заголовок-хук в верхней зоне (текст задаёт админ при переделке или шаблон).
- Шрифты устанавливаются в Docker-образ (иначе libass молча подменит гарнитуру и поедут метрики/кириллица).
Символы, отсутствующие в выбранном шрифте (эмодзи, редкие глифы, латиница в нестандартной гарнитуре), вырезаются на этапе генерации `.ass`, чтобы libass не подставлял чужой шрифт и не ломал метрики строки.

### 3.6. Рендер (ffmpeg, один проход)

- Кадр 1080×1920: исходный клип **сохраняется целиком, без кропа и зума** (fit: contain), свободное место сверху/снизу заполняется размытой копией того же кадра на весь кадр (`gblur`/`boxblur`).
- Поверх — субтитры (`.ass`).
- Кодирование: `libx264`, `preset medium`, `crf 20`; аудио AAC 192 kbps.
- Ожидаемое время рендера клипа 30–60 сек: 1–4 мин на CPU VPS.
**Частота кадров:** по умолчанию `fps: auto` — берётся из исходника, но не выше 60. При исходнике 60 fps допускается даунсемпл до 30 (экономия времени рендера), решение фиксируется в конфиге, а не в коде.

**Контроль размера:** после рендера проверяется размер файла. Если он > 45 МБ, выполняется до 2 повторных кодирований с шагом `crf += 4` (20 → 24 → 28) на уже готовом файле, без повторной сборки фильтр-графа. Если и после этого файл > 45 МБ — админу уходит файл как документ + предупреждение, модерация №2 продолжается по ссылке на локальный файл.

### 3.7. Модерация №2 (готовое видео)

- Бот отправляет готовый ролик админу с кнопками:
  - **Опубликовать** → загрузка в R2, статус `published`, уведомление со ссылкой на объект;
  - **На переделку** → возврат в `rendering` (без повторной транскрипции). В v1 переделка поддерживает: правку текста субтитров, включение/выключение karaoke-режима, установку/снятие хука. Обрезка не нужна: клипы длиннее 60 сек в систему не попадают;
  - **Отказ** → клип помечается `rejected`, файлы удаляются. Отказ действует **только на конкретный клип**; автор в чёрный список не попадает (в v1).
- Комментарий админа сохраняется в БД вместе с версией рендера.
Правка текста субтитров принимается сообщением до 1000 символов; переносы строк и разбивка по словам пересчитываются автоматически по сохранённым таймкодам. Если новый текст не выравнивается по числу слов с исходным транскриптом, правка отклоняется с понятным сообщением админу (таймкоды не «досочиняются»).

### 3.8. Публикация

- R2 (S3-совместимое API, boto3): `YYYY/MM/DD/<clip_id>.mp4` + `meta.json`.
- `meta.json` (UTF-8, `schema_version: 1`):

```json
{
  "schema_version": 1,
  "clip_id": "SomeClipSlug",
  "clip_url": "https://clips.twitch.tv/SomeClipSlug",
  "channel": { "login": "streamer", "display_name": "Streamer", "url": "https://twitch.tv/streamer" },
  "category": { "id": "29595", "name": "Dota 2" },
  "clip": { "title": "...", "duration_sec": 42.3, "views": 12345, "created_at": "2026-11-20T18:03:00Z" },
  "render": {
    "version": 1, "width": 1080, "height": 1920, "fps": 30, "duration_sec": 42.2,
    "video_codec": "h264", "audio_codec": "aac", "size_bytes": 21400000,
    "crf": 20, "subtitles_mode": "karaoke", "hook_text": null, "subtitle_language": "ru"
  },
  "source": { "transcribe_provider": "faster-whisper", "model": "medium" },
  "published_at": "2026-11-25T21:14:00Z",
  "status": "published"
}
```

Поля `render.version` и `published_at` обязательны; при повторной публикации версии ключ объекта не меняется, а `meta.json` перезаписывается с новым `version`.

**Ретеншн:** мастера в R2 хранятся `publish.retention_days` (по умолчанию 180) и удаляются lifecycle-правилом бакета. Правило настраивается один раз вручную, код его не создаёт.
- После успешной загрузки — очистка локальных TEMP-файлов клипа.
- Непосредственная отправка в соцсети (TikTok/YouTube API) — вне scope первой версии; результат публикации — наличие готового файла в R2. Отправку в соцсети админ выполняет вручную или через планировщик на следующем этапе.

### 3.9. Уведомления администратору

- Новый кандидат на модерацию.
- Готовое видео на модерацию.
- Ошибки (`failed` после ретраев).
- Ежедневная сводка: сколько найдено/одобрено/опубликовано.
Кандидат, отправленный на модерацию №1, «протухает» через `parser.candidate_ttl_hours` (по умолчанию 24 ч): если админ не нажал ни одну кнопку, клип переходит в `rejected` с причиной `expired`, карточка в TG редактируется (кнопки убираются, добавляется пометка «просрочено»). Просроченные клипы не блокируют очередь и не считаются в ежедневной сводке как отказы админа.

### 3.10. Конфигурация

- `.env`: токены (Telegram-бот, Twitch Client ID/Secret, R2: account, access key, secret, bucket), ID админа.
- `config.yaml`: фильтры парсера, интервал опроса, модель Whisper, параметры стиля субтитров, параметры рендера, лимиты очереди.
- Редактирование фильтров без перезапуска — командой в TG (опция: `/filters`).

|---|---|

| Минимальный сервер | 2 vCPU, 4 GB RAM, 40 GB SSD |

| Ретеншн мастеров в R2 | 180 дней, lifecycle-правило бакета |

## 5. Ограничения и риски

1. **Авторские права и ToS Twitch.** Скачивание клипов сторонними средствами не покрыто официальным API. Система предназначена для внутреннего использования; администратор отвечает за соблюдение прав авторов и правил платформ публикации.
2. **Нестабильность источников скачивания** — обходится сменой механизма в одном модуле.
3. **Качество распознавания** (жаргон, шум, музыка) — предусмотрена правка субтитров админом на этапе «на переделку» (правка текста → повторный рендер без повторной транскрипции).
4. **Нестабильность расшифровки таймкодов LLM** — не используется: таймкоды берутся только из Whisper.

## 6. Этапы работ

| Этап | Состав | Результат |
|---|---|---|
| 0. Каркас репозитория | Структура, документация, журналы, шаблоны конфигов | Готовый к работе репозиторий (выполнено) |
| 1. Каркас приложения | Структура кода, docker-compose, SQLite-схема и статусы, конфиг, бот-скелет, worker-loop | Развёрнутый пустой бот |
| 2. Парсер | Helix API, фильтры, дедуп, карточки в TG с кнопками | Кандидаты приходят админу |
| 3. Конвейер | Скачивание → Whisper → .ass → ffmpeg-рендер → модерация №2 | Готовое вертикальное видео |
| 4. Публикация | R2, meta.json, очистка, уведомления, ежедневная сводка | Полный цикл |
| 5. Доработки | Контентные фильтры, karaoke-стили, LLM-нормализация субтитров, публикация в соцсети | Расширение |

**Критерий готовности этапа 4:** цикл «найден клип → одобрен → отрендерен → опубликован в R2» проходит без участия разработчика, 3–5 видео в день выдерживается на сервере минимальной конфигурации.

## 7. Вне scope (первая версия)

- Автоматическая публикация в TikTok / YouTube Shorts / Instagram Reels через API.
- Мультиканальность (несколько TG-админов / несколько выходных каналов).
- Автоматический подбор хуков/заголовков через LLM (Grok/GPT) — предусмотрена точка расширения.
- Контентная классификация клипов на этапе парсинга.
- LLM-нормализация текста субтитров — точка расширения (§3.4).

## 8. Уточнения к версии 1.0 (приняты заказчиком 25.11.2026)

| № | Вопрос | Решение |
|---|---|---|
| U-1 | Клипы длиннее 60 сек | В систему не попадают: парсер фильтрует `duration ≤ 60`. Тримминг на рендере не реализуется. |
| U-2 | Кадрирование исходника | Кадр сохраняется целиком (contain, без кропа и зума); свободное место закрывается размытой копией кадра. |
| U-3 | Что умеет «На переделку» в v1 | Правка текста субтитров, karaoke on/off, хук текстом. Перерендер без повторной транскрипции. |
| U-4 | «Отказ» и чёрный список автора | Отказ — только по конкретному клипу. Автор не банится. |
| U-5 | Нехватка кандидатов для 3–5 видео/день | Не обрабатывается: считается, что кандидатов достаточно; авто-расширение фильтров не делаем. |
| U-6 | Чем делаются субтитры | faster-whisper (`ru`, word timestamps) → наш генератор `.ass` → libass в ffmpeg (`ass=`). Внешние ASR-API возможны только через интерфейс `transcribe()`. |
| U-7 | Сторонние LLM для качества субтитров | В v1 не используются. Сначала `initial_prompt` + `glossary`. LLM-нормализация — опциональный флаг на этапе 5, с инвариантом числа слов и фолбэком. Таймкоды — только Whisper. |
